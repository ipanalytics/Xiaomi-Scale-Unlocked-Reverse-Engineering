# Грабли со стороны сбора

_English version: [pitfalls.md](pitfalls.md)_

Ловушки, на которые я наступил, пока заводил эти кадры в базу. Некоторые стоили вечера.

## Донгл — главная ловушка

Не всякий USB-Bluetooth-донгл умеет роль LE-централи, без которой сканирование невозможно. Дешёвые донглы на CSR-кремнии (USB ID `0a12:0001`) встречаются часто и нередко поддерживают только классический BR/EDR. Отказ тихий:

```
$ btmgmt info
    supported settings: powered connectable discoverable bondable link-security br/edr ...
```

Если в этом списке нет `le`, радио не увидит рекламу никогда. Сканер падает с `No Bluetooth adapters with BLE 'central' role found`, и никакая перезагрузка драйверов не помогает. Перед покупкой проверять `btmgmt info` (или даташит чипсета): нужен донгл, у которого `le` в поддерживаемых настройках. Один из моих двух донглов оказался CSR-деталюшкой только с классическим Bluetooth, и для этой задачи он бесполезен.

## Не сопрягать

Сопряжение не нужно и мешает: часть приборов после привязки перестаёт рекламироваться для всех остальных, а приложение производителя и коллектор начинают драться за соединение. Читать рекламу и ничего не трогать.

## Радио одно — делить его аккуратно

Один адаптер, несколько приборов. Непрерывный скан держит радио занятым и может мешать GATT-клиенту на том же адаптере — другой сборщик, переподключающийся по своему расписанию (тонометр, нагрудный пульсометр), начнёт терять сеансы. Сканировать окнами (пять минут вокруг взвешивания), а не круглосуточно. Если второй прибор перестал отдавать данные — подозревать в первую очередь скан.

## Фильтровать до записи

Стабилизирующийся вес рассылается несколько раз в секунду, и значение плывёт, пока человек устаивается. Хранить только кадры с установленным битом стабилизации, а кадр со снятой нагрузкой считать «на весах никого», а не измерением. Без этого фильтра история забьётся сотнями почти одинаковых строк и одной случайной записью на 0,1 кг.

## Дедуплицировать на записи, а не в коде

Дать хранилищу уникальный ключ по прибору, времени и метрике и писать через `INSERT OR IGNORE`. Пассивный сбор идемпотентен по своей природе: повторный прогон той же записи не должен создавать вторую строку.

## Адреса и идентичность

Эти весы рекламируются с публичным, стабильным адресом — именно это даёт пригодный ключ прибора. Не исходить из этого для любого устройства: многие BLE-периферии меняют адрес ради приватности, и их надо сопоставлять по имени или manufacturer data.

## Верить записи, а не часам

Поле времени читается как 1970, пока часы не выставит приложение производителя. С кадром всё в порядке — часы никогда не выставляли. Время получения берётся своё, а приборное остаётся подсказкой.

## Перезаписывать после обновления прошивки

Разметка, вскрытая по рекламе, может измениться, когда производитель выпустит обновление прошивки. Если числа перестали сходиться — записать свежий сеанс с известным весом, прежде чем решать, что прибор умер.

## Права

Сканирование через BlueZ идёт по системному D-Bus. В большинстве дистрибутивов коллектору нужен root или явное правило политики; скан, который вообще ничего не возвращает, — это обычно проблема прав.
