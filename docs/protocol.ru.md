# Протокол рекламных пакетов весов Xiaomi

_English version: [protocol.md](protocol.md)_

Что весы кладут в свой рекламный пакет — поле за полем, с разобранными примерами.

## Транспорт

Измерение идёт в service data внутри рекламного пакета. В семействе используются два UUID:

- `0000181d-0000-1000-8000-00805f9b34fb` — payload 10 байт (Mi Smart Scale)
- `0000181b-0000-1000-8000-00805f9b34fb` — payload 13 байт (Mi Body Composition Scale)

Имя прибора в эфире зависит от модели; имя `MIBFS` типично для поколения с составом тела. Ничего в payload не зашифровано, подключение не требуется.

## Версия 2 — 13 байт (`0x181B`)

| Смещение | Размер | Поле | Заметки |
| --- | --- | --- | --- |
| 0 | 1 | заголовок | всегда `0x02` |
| 1 | 1 | флаги | см. ниже |
| 2-3 | 2 | год | little-endian; читается как 1970, если часы никогда не выставляли |
| 4 | 1 | месяц | 1-12 |
| 5 | 1 | день | 1-31 |
| 6 | 1 | час | 0-23 |
| 7 | 1 | минута | 0-59 |
| 8 | 1 | секунда | 0-59 |
| 9-10 | 2 | импеданс | little-endian, в омах; `0xFFFD`, когда измерение импеданса не проводилось |
| 11-12 | 2 | вес | little-endian; делить на 200, чтобы получить килограммы |

Байт флагов, по битам:

| Бит | Маска | Значение |
| --- | --- | --- |
| 1 | `0x02` | 1 = импеданс есть в байтах 9-10 |
| 5 | `0x20` | 1 = вес стабилизирован |
| 7 | `0x80` | 1 = нагрузка снята (на весах никого) |

Биты 0, 2, 3, 4 и 6 в этом семействе не используются.

## Версия 1 — 10 байт (`0x181D`)

| Смещение | Размер | Поле | Заметки |
| --- | --- | --- | --- |
| 0 | 1 | управляющий байт | `0x22` измерение, `0xA2` стабилизировано |
| 1-2 | 2 | вес | little-endian, делить на 200 |
| 3-4 | 2 | год | little-endian |
| 5 | 1 | месяц | |
| 6 | 1 | день | |
| 7 | 1 | час | |
| 8 | 1 | минута | |
| 9 | 1 | секунда | |

В версии 1 поля импеданса нет.

## Разобранные примеры

Стабилизированное взвешивание, 75,0 кг:

```
кадр: 02 24 b2 07 01 04 03 06 37 fd ff 98 3a
      │  │  └──┬──┘ └─────┬─────┘ └──┬──┘ └──┬──┘
      │  │     │          │          │       └ 98 3a → 0x3a98 = 15000 → /200 = 75,0 кг
      │  │     │          │          └───────── импеданс не измерялся (0xfffd)
      │  │     │          └──────────────────── 1970-01-04 03:06:55 (часы не выставляли)
      │  │     └─────────────────────────────── год, little-endian
      │  └───────────────────────────────────── флаги: стабилизировано, импеданса нет, нагрузка есть
      └──────────────────────────────────────── заголовок
```

Те же весы сразу после схода:

```
кадр: 02 84 b2 07 01 04 03 07 26 00 00 14 00
вес: 14 00 → 0x0014 = 20 → /200 = 0,1 кг, во флагах отмечена снятая нагрузка
```

Кадр версии 1, 75,75 кг:

```
кадр: 22 2e 3b b2 07 01 01 00 36 15
вес: 2e 3b → 0x3b2e = 15150 → /200 = 75,75 кг
```

## Заметки по полям

- **Разрешение веса** — 5 грамм на сырую единицу, то есть кг = сырое / 200. Весы устаиваются шагом 50 г.
- **Стабилизация и промежуточные кадры.** Пока человек устаивается, прибор шлёт кадры со снятым битом стабилизации и плывущим весом. Хранить только стабилизированные.
- **Снятая нагрузка.** Кадры со снятой нагрузкой недолго держат последний вес, затем падают до значения пустых весов — на моём экземпляре это одна десятая килограмма. Это «на весах никого», а не измерение.
- **Импеданс** появляется только тогда, когда взвешивание шло с включённым импедансом: босые стопы и сеанс, который прибор считает измерением состава тела. Когда его нет, бит остаётся снятым, а байты 9-10 несут `0xFFFD`.
- **Часы** ровно настолько точны, насколько давно синхронизировались с приложением производителя. Весы, которые никогда не сопрягали, показывают 1970 год; остальные поля разборщик всё равно отдаёт.
- **Пути через GATT нет.** В семействе есть ещё служебный сервис производителя, требующий токена авторизации, и без него характеристика веса ничего не отдаёт. Всё нужное лежит в рекламном пакете, и ключ для него не нужен.
