# Xiaomi-Scale-Unlocked-Reverse-Engineering

_English version: [README.md](README.md)_

Весы Mi рассылают каждое измерение прямо в рекламном BLE-пакете. Здесь эта разметка — байт за байтом — и офлайн-разборщик к ней.

## Обзор

Мне нужна история веса в базе, которой я распоряжаюсь, а не за логином производителя. Весы отдают измерение сами: оно лежит в рекламном пакете, который прибор рассылает несколько раз в секунду, — значит хватает пассивного скана. Ни подключения, ни сопряжения, ничего в прибор не пишется. Xiaomi этот payload не документирует, поэтому разметка ниже — из моей собственной записи этих кадров.

Два поколения одного семейства:

- `0x181D`, 10 байт — Mi Smart Scale
- `0x181B`, 13 байт — Mi Body Composition Scale (в эфире как `MIBFS`)

## Разметка кадра

Версия 2, 13 байт (`0x181B`):

| Байты | Поле | Кодирование |
| --- | --- | --- |
| 0 | заголовок | `0x02` |
| 1 | флаги | `0x02` есть импеданс, `0x20` вес стабилизирован, `0x80` нагрузка снята |
| 2-3 | год | little-endian, 16 бит |
| 4-8 | месяц, день, час, минута, секунда | по одному байту |
| 9-10 | импеданс | little-endian, 16 бит; `0xFFFD`, когда его нет |
| 11-12 | вес | little-endian, 16 бит; делить на 200, чтобы получить килограммы (сырая единица 5 г) |

Версия 1, 10 байт (`0x181D`): управляющий байт (`0x22` измерение, `0xA2` стабилизировано), вес в байтах 1-2 с тем же множителем, далее год, месяц, день, час, минута, секунда.

Полные пояснения по полям, поведение флагов и разобранные примеры: [docs/protocol.ru.md](docs/protocol.ru.md).

## Быстрый старт

```bash
python3 -m unittest discover -s tests
python3 tools/xiaomi_scale_decode.py -f examples/frames.txt
python3 tools/xiaomi_scale_decode.py 0224b2070104030637fdff983a
python3 tools/body_composition.py --weight 65 --height 172 --age 35 --sex female --impedance 560
```

Hex-кадры принимаются с пробелами, двоеточиями или дефисами; строки, начинающиеся с `#`, пропускаются — значит в файле записи можно держать комментарии. Каждый читаемый кадр превращается в один JSON-объект:

```json
{"version": 2, "weight_kg": 75.0, "impedance": null, "stabilized": true, "load_removed": false, "timestamp": "1970-01-04T03:06:55"}
```

## Сбор

Разборщик офлайновый: он превращает hex-кадры в записи. Кадры снимают любым сканером, который умеет печатать service data; оставляют только кадры с установленным битом стабилизации, отбрасывают запись со снятой нагрузкой, а остальное кладут под уникальный ключ, чтобы повторы рекламы схлопывались в одну строку. Про выбор адаптера, окна сканирования и грабли, на которые я наступил: [docs/pitfalls.ru.md](docs/pitfalls.ru.md).

## Границы и ограничения

- Разметка привязана к этому семейству приборов; формат Xiaomi ничего не говорит о весах другой марки.
- Разбор рекламы даёт только измерение. Я не трогаю то, что приложение производителя делает поверх: синхронизацию истории, алгоритмы состава тела, обновления прошивки.
- В кадре лежит сырой импеданс. Цифры по жиру, воде, мышцам, костям, белку, висцеральному жиру, BMR и метаболическому возрасту — это арифметика поверх веса, импеданса, роста, возраста и пола: формулы и оговорки в [docs/body-composition.ru.md](docs/body-composition.ru.md).
- Поле времени бесполезно у весов, часы которых никогда не выставляли приложением: год читается как 1970. Вес и флаги от этого не зависят.
